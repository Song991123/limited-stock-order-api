# API 명세

기본 주소는 `http://127.0.0.1:18086`입니다. 시험 계정 alice와 bob을 사용하며 비밀번호는 실행할 때 생성합니다. 요청 예제는 `scripts/demo-request.ps1`에 있습니다.

## 인증과 변경 요청

HTTP Basic 인증 뒤 `GET /csrf`로 세션과 토큰을 받습니다. POST 요청에는 같은 세션 쿠키와 응답의 `headerName`에 해당하는 토큰을 보냅니다. 고객 ID는 서버가 인증 계정에서 구합니다.

CSRF 토큰은 요청 헤더로 전송하며 폼 본문으로 대신하지 않습니다. 주문 입력은 JSON, 취소는 본문 없이 보냅니다. 크기 초과 요청은 인증/CSRF 검사보다 먼저 413으로 거절할 수 있습니다.

## 주문 접수

```http
POST /orders
Idempotency-Key: example-request-001
Content-Type: application/json

{"productId":1,"quantity":2}
```

상품 ID와 수량은 양의 정수입니다. 키는 영문, 숫자, 하이픈과 밑줄 1~128자입니다. 같은 구매의 재시도에는 키와 입력을 유지하고, 별도로 구매할 때 새 키를 사용합니다.

| 조건 | 결과 |
| --- | --- |
| 새 구매이며 재고 확보 | 201, Location과 접수된 주문 |
| 같은 고객/키/상품/수량 | 200, 원래 주문의 현재 상태 |
| 같은 고객/키에 다른 상품이나 수량 | 409 `IDEMPOTENCY_KEY_REUSED` |
| 재고 부족 | 409 `OUT_OF_STOCK`, 해당 키의 거절 결과 보존 |
| 재고 부족 뒤 재고가 복구됨 | 이전 키는 같은 거절. 새 구매 키는 재고 재판정 |
| 원래 주문 취소 뒤 생성 요청 재전송 | 같은 취소 주문 반환, 추가 차감 없음 |

주문 응답의 필드는 `id`, `productId`, `quantity`, `status`, `createdAt`, `cancelledAt`입니다. 상태는 ACCEPTED와 CANCELLED입니다. 서버가 커밋한 뒤 응답합니다.

## 조회와 취소

- `GET /products`: 최대 100개 시험 상품의 이름과 현재 수량.
- `GET /products/{id}`: 해당 상품. 조회와 주문 사이 수량이 바뀔 수 있음.
- `GET /orders?limit=20&beforeId=123`: 자기 주문을 ID 내림차순으로 조회. limit은 1~100, 다음 조회에 마지막 ID 사용.
- `GET /orders/{id}`: 자기 주문의 현재 상태.
- `POST /orders/{id}/cancel`: 본문 없이 요청. 접수 주문의 상태와 수량을 함께 복구. 이미 취소됐으면 현재 취소 주문 반환.

같은 취소 요청은 주문 ID와 상태 조건으로 구별합니다. 다른 고객의 주문 조회와 취소는 404입니다.

## 오류와 재시도

서비스 처리 오류는 `{"code":"OUT_OF_STOCK"}` 형태로 반환합니다. 입력이나 SQL의 내부 값은 오류 응답에 넣지 않습니다.

| 응답 | 다음 행동 |
| --- | --- |
| 400 | 입력/키/불필요한 취소 본문을 수정 |
| 401 / 403 | 인증 또는 CSRF 세션과 토큰 확인 |
| 404 | 상품/주문 또는 접근 계정 확인 |
| 409 | 재고 부족과 키 충돌을 구별. 같은 요청을 자동 반복하지 않음 |
| 413 | 요청 본문 축소. 고정 길이와 chunked 모두 8KiB로 제한 |
| 429 + Retry-After | 동시 진입 한도는 1초, 고객별 한도는 다음 고정 1분 구간까지 남은 초 뒤 제한 재시도. 같은 구매 키 유지 |
| 503 + Retry-After | 일시적 DB 접속/잠금 문제. 같은 구매 키로 제한 재시도 |
| 500 | 내부 정합성 또는 저장 오류. 성공으로 처리하지 않고 오류 기록 확인 |

커밋 중 연결이나 HTTP 응답을 잃으면 확정 여부가 모호할 수 있습니다. 주문은 같은 키, 취소는 같은 주문 ID로 결과를 확인합니다. 새 키로 무조건 다시 주문하지 않습니다.

쓰기 동시 처리 32건, 계정별 고정 1분 구간 120건, DB 잠금 대기 3초와 SQL 문장 제한 8초는 로컬 실행 정책값입니다. 운영 수용량이나 성능 측정 결과가 아닙니다. 요청량 한도는 한 JVM 안에서 적용합니다. 고정 구간 경계의 연속 요청을 평탄화하는 방식은 아니며 `Retry-After`도 재고나 처리 슬롯의 예약을 뜻하지 않습니다.
